# A JSON bank format with a published JSON Schema, rather than QTI

Question banks are authored by teachers and by AI assistants, and "standard" could have meant adopting an existing assessment standard. We chose a single JSON document with a published JSON Schema (generated from the Zod types the app validates with, so the two cannot drift), served from the deployed app so a bank's `$schema` key points at a real URL and editors give authors autocomplete and inline errors while they write.

QTI 3.0 is the genuine industry standard and was rejected deliberately: it is verbose XML, most of its surface is irrelevant to single-choice physics questions, it is unpleasant to hand-write, and it would have made the parser a significant part of the app rather than a footnote. GIFT and Aiken are easier to write but are Moodle-flavoured plain text with an ad hoc grammar and poor error reporting, which matters because clear validation errors are the main thing standing between a teacher and adoption. An importer converting GIFT or QTI into this format is additive and can be built later without touching the app.

Two consequences are worth recording. First, the schema is `.strict()`: unknown keys fail loudly, so a typo like `explaination` is a load-time error rather than a bank that silently has no explanations. Second, LaTeX inside JSON is a real trap, because `"\times"` parses as a tab character followed by `imes` with no error at all. We mitigate it three ways: the validator detects stray control characters in strings and names the likely cause, the documentation shouts about doubling backslashes, and the app accepts YAML banks validated against the identical schema, where single-quoted scalars need no escaping.
